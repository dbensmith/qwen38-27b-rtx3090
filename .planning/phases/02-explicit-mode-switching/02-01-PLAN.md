**Flagged planner assumptions (explicit, never silent):**

- **A-1 (SWITCH-02 concurrency probe — unresolved by design):** switch.sh holds no lock. Two
  *concurrent* invocations could interleave stop/up and transiently violate the one-GPU
  invariant or race the state-file write. Assumption: single-user host, human-initiated script,
  never invoked in parallel — no decision in D-01..D-07 mandates locking, and adding it would
  exceed the locked scope. Guaranteed floor even under a race: the write-after-success ordering
  (truth 3) means `.current-profile` only ever names a profile that actually came up.
- **A-2 (D-06 mechanism finding — decision honored as locked, outcome asserted):** D-06 locks
  "switch.sh exports KV_MEM=5583457484 only when unset ... no new plumbing". Docker Compose does
  not forward arbitrary host-shell exports into containers for this compose file
  (`docker-compose.yml` has no `environment:`/pass-through reference to `KV_MEM`; `env_file: .env`
  injects file contents only). The container-side pin outcome is nonetheless guaranteed by
  `single-user/start_qwen.sh:369`'s own set-if-unset default with the **byte-identical value**
  5583457484, mapped to `--kv-cache-memory` at :433 — so the export (implemented exactly per
  D-06) and the in-container default can never disagree, and a `.env` override reaches the
  container via `env_file` and wins at both layers. The executor MUST NOT "fix" the inheritance
  by editing `docker-compose.yml` or `.env` (secret-guarded) — Task 1's verify asserts the
  OUTCOME where it matters: the exact pin flag in the running container's vLLM argv.
