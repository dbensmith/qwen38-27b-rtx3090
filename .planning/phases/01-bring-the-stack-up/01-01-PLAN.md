<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host filesystem -> `.env` | Real secret material (`VLLM_API_KEY`) lands in a plaintext file on disk once, via `op inject` |
| 1Password vault -> `op inject` | The CLI pulls a live secret value across the desktop-app integration boundary into local process memory then onto disk |
| External network -> vLLM HTTP API (`0.0.0.0:18020`) | Both `single` and `batch` bind all interfaces per docker-compose.yml's port mapping; anyone who can reach the host on that port reaches the inference API |
| `.env` -> both containers | The same `env_file: .env` wiring feeds `single` and `batch` identically — a boundary crossed by every knob in the file, not just the ones each script actually reads |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `.env` (generated secret file, repo root) | medium | mitigate | Task 1 verifies `git check-ignore .env` exits 0 before treating generation as done (existing `.gitignore`/`.dockerignore` already exclude it); no task action ever `cat`s the full `.env` or logs its contents — only targeted `grep` on the two non-secret WSL2 keys |
| T-01-02 | Spoofing | vLLM HTTP API (binds `0.0.0.0:18020`, per CONCERNS.md's existing finding) | high | mitigate | Task 1's acceptance criteria require `.env`'s `VLLM_API_KEY=` line to be non-empty and NOT the literal `op://...` ref after `op inject` runs — a silent injection failure that left the server unauthenticated on a world-bindable port is caught here rather than assumed away |
| T-01-03 | Tampering | `op inject` secret pipeline (1Password desktop-app integration) | medium | accept | The integration was confirmed live before planning (`op read` against the exact op-ref returned a value in this session); `op inject` fails loud (non-zero exit) rather than silently writing a partial `.env`, and Task 1's verify chain checks that exit code |
| T-01-04 | Denial of Service | GPU memory / VRAM (cold-start profiling race between stopping `single` and starting `batch`) | medium | mitigate | Task 2 mirrors the repo's own established `single-user/qwen-serving.service` `ExecStartPre` GPU-free-wait loop (poll `nvidia-smi` until used memory is under 1000 MiB) before `docker compose --profile batch up -d`, per docs/gotchas.md #2 |

</threat_model>
